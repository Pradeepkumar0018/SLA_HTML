Question 1: Difference between DBMS and RDBMS
DBMS (Database Management System):
- Stores data as files, no mandatory relationship between data.
- Does not support normalization.
- No concept of keys (primary/foreign) or constraints.
- Not necessarily suited for large data volumes.
- Example: XML files, file systems.

RDBMS (Relational DBMS):
- Stores data in tables (rows and columns).
- Supports relationships between tables using Primary Key / Foreign Key.
- Supports normalization to reduce redundancy.
- Enforces data integrity (constraints, ACID properties).
- Example: MySQL, PostgreSQL, Oracle, SQL Server.

Question 2: DDL, DML, DQL, DCL, TCL (with examples)
1. DDL (Data Definition Language) - defines/modifies structure
   Example:
   CREATE TABLE Employees (id INT, name VARCHAR(50));

2. DML (Data Manipulation Language) - modifies data
   Example:
   INSERT INTO Employees (id, name) VALUES (1, 'Arun');

3. DQL (Data Query Language) - retrieves data
   Example:
   SELECT * FROM Employees;

4. DCL (Data Control Language) - controls access/permissions
   Example:
   GRANT SELECT ON Employees TO 'user1';

5. TCL (Transaction Control Language) - manages transactions
   Example:
   COMMIT;
   -- or
   ROLLBACK;

Question 4: DELETE vs TRUNCATE vs DROP

DELETE:
- Removes rows one at a time (can use WHERE clause).
- Can be rolled back (DML, logged).
- Table structure remains.
Example:
DELETE FROM Employees WHERE id = 3;

TRUNCATE:
- Removes ALL rows at once, resets identity/auto-increment.
- Cannot use WHERE clause.
- Faster than DELETE, minimal logging.
- Table structure remains.
Example:
TRUNCATE TABLE Employees;

DROP:
- Removes the entire table (structure + data) from the database.
- Cannot be rolled back in most databases.
Example:
DROP TABLE Employees;

Summary:
DELETE = remove specific/all rows (data only, slow, logged)
TRUNCATE = remove all rows (data only, fast, structure kept)
DROP = remove entire table (structure + data gone)

Question 5: CHAR vs VARCHAR

CHAR(n):
- Fixed length. Always uses 'n' characters of storage, padding with spaces if the value is shorter.
- Faster for fixed-length data.
- Use when data length is constant (e.g., gender 'M'/'F', country code).
Example: CHAR(2)

VARCHAR(n):
- Variable length. Uses only as much storage as the actual data needs (+ small overhead).
- Saves space when lengths vary.
- Use when data length varies (e.g., name, email, address).
Example: VARCHAR(100)

When to use:
- CHAR: fixed-size codes (e.g., 'IN', 'US', gender).
- VARCHAR: names, addresses, descriptions, or any text with variable length.

Question 9: WHERE vs HAVING

WHERE:
- Filters individual rows BEFORE grouping/aggregation.
- Cannot be used with aggregate functions directly.

HAVING:
- Filters groups AFTER GROUP BY / aggregation.
- Used with aggregate functions like SUM(), COUNT(), AVG().

Example using WHERE:
SELECT * FROM Employees
WHERE salary > 50000;

Example using HAVING:
SELECT department, AVG(salary) AS avg_salary
FROM Employees
GROUP BY department
HAVING AVG(salary) > 50000;

Question 15 (Interview Challenge): Full Report

SELECT
    department,
    COUNT(*) AS employee_count,
    SUM(salary) AS total_salary,
    AVG(salary) AS average_salary,
    MAX(salary) AS highest_salary,
    MIN(salary) AS lowest_salary
FROM Employees
WHERE salary > 40000
  AND city = 'Chennai'
GROUP BY department
HAVING COUNT(*) > 2
   AND AVG(salary) > 60000
ORDER BY total_salary DESC
LIMIT 3;

Explanation of flow:
1. WHERE filters rows first (salary > 40000 AND city = 'Chennai').
2. GROUP BY groups the filtered rows by department.
3. HAVING filters the grouped results (employee_count > 2 AND avg_salary > 60000).
4. ORDER BY sorts the final groups by total_salary descending.
5. LIMIT restricts output to the top 3 departments.



1. Difference between COUNT(*) and COUNT(column)?
   - COUNT(*) counts ALL rows, including rows where columns have NULL values.
   - COUNT(column) counts only the rows where that specific column is NOT NULL.
   Example: If 2 employees have NULL salary, COUNT(*) still counts them,
   but COUNT(salary) will exclude them.

2. Can HAVING be used without GROUP BY?
   - Yes. In that case, HAVING treats the entire table as a single group.
   Example:
   SELECT COUNT(*) FROM Employees HAVING COUNT(*) > 10;

3. Can WHERE and HAVING be used together?
   - Yes. WHERE filters rows before grouping, and HAVING filters the
     grouped/aggregated results afterward. Both can be used in the same query.

4. What is the execution order of a SQL query?
   Logical execution order (not the order you write it in):
   1. FROM (and JOINs)
   2. WHERE
   3. GROUP BY
   4. HAVING
   5. SELECT
   6. ORDER BY
   7. LIMIT / OFFSET

5. Which executes first: WHERE or GROUP BY?
   - WHERE executes first. It filters individual rows before they are
     grouped by GROUP BY. HAVING then filters the resulting groups.
